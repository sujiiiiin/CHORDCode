# Prompt Creation And Evaluation

CHORD optimization works best when the video model can generate the desired motion conditioned on static renders of the scene. This guide describes two scripts for choosing a prompt before starting a long training run: one script asks a VLM to suggest feasible motion prompts for a scene, and the other script tests candidate prompts by generating videos using the video model and optionally asking a VLM to score motion adherence and video quality.

By default the scripts use [Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) as the VLM. You can instead pass `--vlm gpt` or `--vlm gemini` if those API clients are configured.

## Suggest Candidate Prompts

Render several static Gaussian views and ask the VLM for feasible motion prompts:

```bash
python scripts/prompting/suggest_motion_prompts.py -m trained/<scene_name> --mesh_source_path data/<scene_name> --azims 0 90 180 270 --elev 10.0 --cam_radius <camera_radius> --num_prompts 10 --output_dir trained/<scene_name>/prompt_suggestions --overwrite
```

Important arguments:

`-m` and `--mesh_source_path` point to the fitted Gaussians and original meshes for the scene. `--azims`, `--elev`, and `--cam_radius` choose the static views shown to the VLM; use views that clearly show the objects whose motion you care about. If `--azims` is not set, the script renders `--num_views` uniformly spaced azimuths between `--azim_l` and `--azim_r`. `--num_prompts` controls how many candidate prompts to request. `--output_dir` stores the rendered views and final prompt list.

This writes:

- `renders/`: multiview Gaussian stills shown to the VLM.
- `prompt_suggestions.txt`: plain-text prompt list.

<details>
<summary><span style="font-weight: bold;">Command Line Arguments for scripts/prompting/suggest_motion_prompts.py</span></summary>

  #### -m

  Path to the fitted 3D Gaussian directory for the scene, such as `trained/<scene_name>`.

  #### --mesh_source_path

  Path to the scene mesh directory, such as `data/<scene_name>`.

  #### --obj_num

  Number of object meshes in the scene. The default `-1` auto-detects this from the top-level `obj_i.glb` files in the mesh directory.

  #### --azims

  Explicit azimuth angles, in degrees, for the multiview static renders shown to the VLM.

  #### --num_views

  Number of uniformly spaced azimuth views to render when `--azims` is not provided.

  #### --elev

  Camera elevation, in degrees. Positive values place the camera above the scene.

  #### --cam_radius

  Camera distance from the scene center. Use the same rough value you expect to use for CHORD training.

  #### --exclude_objs

  Object names to omit from the static prompt renders, such as `obj_0 obj_2`.

  #### --no_bg

  Omit the static background object from the prompt renders.

  #### --vlm

  VLM provider used for prompt suggestion. The default is `qwen_local`; `gpt` and `gemini` are optional API-based alternatives.

  #### --qwen_model_path

  Local Qwen model identifier or path used when `--vlm qwen_local` is selected. The default is `Qwen/Qwen3.6-35B-A3B`.

  #### --qwen_device

  Device placement for local Qwen. Use `cuda` for one GPU or `auto` to let Transformers place the model.

  #### --qwen_max_new_tokens

  Maximum number of new tokens generated by local Qwen.

  #### --num_prompts

  Number of candidate prompts to request from the VLM.

  #### --output_dir

  Directory where rendered views and prompt suggestions are saved.

  #### --overwrite

  Regenerate outputs even if files already exist.

</details>

## Evaluate Prompts

Use `evaluate_motion_prompt.py` to check whether the video model can generate a candidate prompt from static scene renders. By default, the script saves generated videos for user inspection:

```bash
python scripts/prompting/evaluate_motion_prompt.py -m trained/<scene_name> --mesh_source_path data/<scene_name> --azims 0 90 180 270 --elev 10.0 --cam_radius <camera_radius> --ckpt_dir ./LightX2VModel --size "832*480" --sample_steps 4 --prompt "<prompt>" --output_dir trained/<scene_name>/prompt_eval/<prompt_name> --judge manual --overwrite
```

To ask a VLM to score the generated videos, use `--judge vlm`:

```bash
python scripts/prompting/evaluate_motion_prompt.py -m trained/<scene_name> --mesh_source_path data/<scene_name> --azims 0 90 180 270 --elev 10.0 --cam_radius <camera_radius> --ckpt_dir ./LightX2VModel --size "832*480" --sample_steps 4 --prompt "<prompt>" --output_dir trained/<scene_name>/prompt_eval/<prompt_name> --judge vlm --overwrite
```

You can also ask the VLM to expand the prompt into moderate, physically detailed generation prompts before video generation through passing `--expand_prompts`. In this mode, the script evaluates the original prompt and each expanded prompt:

```bash
python scripts/prompting/evaluate_motion_prompt.py -m trained/<scene_name> --mesh_source_path data/<scene_name> --azims 0 90 180 270 --elev 10.0 --cam_radius <camera_radius> --ckpt_dir ./LightX2VModel --size "832*480" --sample_steps 4 --prompt "<prompt>" --expand_prompts --num_prompt_expansions 4 --output_dir trained/<scene_name>/prompt_eval/<prompt_name> --judge vlm --overwrite
```

With `--judge vlm`, each video is scored from two aspects: `motion_adherence_score` measures whether the visible motion follows the original `--prompt`, and `video_quality_score` measures identity preservation, temporal stability, object consistency, and physical plausibility. For this video-judgment step, we recommend using a stronger API-based VLM such as `--vlm gemini` or `--vlm gpt` when available. The final summary reports the target prompt, the highest-scoring generation prompt, and per-prompt average scores.

Prompt evaluation uses the fast [LightX2V step-distilled model](https://huggingface.co/lightx2v/Wan2.2-Distill-Models) by default as a practical pre-screening model. It is much faster than the full Wan2.2 I2V model, so it is useful for checking prompts and viewpoints before starting CHORD training. The default `--ckpt_dir ./LightX2VModel` should point to the downloaded distilled model; see the [LightX2V repository](https://github.com/ModelTC/LightX2V) for the original project and download instructions. For validation using the full Wan2.2 I2V model, pass `--use_original_wan`.

The evaluation output directory contains:

- `videos/`: generated test videos for each prompt and view.
- `video_validation/`: per-video VLM judgments when `--judge vlm` is used.
- `prompt_expansions.json`: generated prompt expansions when `--expand_prompts` is used.
- `final_verdict.txt` and `final_verdict.json`: target prompt, highest-scoring generation prompt, and motion/quality/combined scores.

<details>
<summary><span style="font-weight: bold;">Command Line Arguments for scripts/prompting/evaluate_motion_prompt.py</span></summary>

  #### -m

  Path to the fitted 3D Gaussian directory for the scene, such as `trained/<scene_name>`.

  #### --mesh_source_path

  Path to the scene mesh directory, such as `data/<scene_name>`.

  #### --obj_num

  Number of object meshes in the scene. The default `-1` auto-detects this from the top-level `obj_i.glb` files in the mesh directory.

  #### --azims

  Explicit azimuth angles, in degrees, for the static reference renders used by video generation.

  #### --num_views

  Number of uniformly spaced azimuth views to render when `--azims` is not provided.

  #### --elev

  Camera elevation, in degrees. Positive values place the camera above the scene.

  #### --cam_radius

  Camera distance from the scene center.

  #### --exclude_objs

  Object names to omit from the static prompt renders, such as `obj_0 obj_2`.

  #### --no_bg

  Omit the static background object from the prompt renders.

  #### --vlm

  VLM provider used for prompt expansion and video judgment. The default is `qwen_local`; `gpt` and `gemini` are optional API-based alternatives.

  #### --qwen_model_path

  Local Qwen model identifier or path used when `--vlm qwen_local` is selected. The default is `Qwen/Qwen3.6-35B-A3B`.

  #### --qwen_device

  Device placement for local Qwen. Use `cuda` for one GPU or `auto` to let Transformers place the model.

  #### --qwen_max_new_tokens

  Maximum number of new tokens generated by local Qwen.

  #### --use_original_wan

  Use the full Wan2.2 I2V model for prompt testing instead of the default LightX2V step-distilled model. This is slower but can be useful for final prompt validation.

  #### --ckpt_dir

  Video-model checkpoint directory. The default `./LightX2VModel` should point to the downloaded LightX2V step-distilled Wan2.2 I2V model; with `--use_original_wan`, the default is `./Wan2.2-I2V-A14B`.

  #### --size

  Video generation resolution, written as `width*height`. The release setting is `832*480`.

  #### --sample_steps

  Number of video-generation sampling steps. The default is `4` for LightX2V prompt testing; with `--use_original_wan`, the default is the Wan2.2 I2V setting, usually `40`.

  #### --frame_num

  Number of frames to generate for each test video.

  #### --prompt

  Candidate motion prompt to evaluate.

  #### --judge

  `manual` saves videos for user inspection. `vlm` also asks the VLM to score each generated video for motion adherence to the original prompt and overall video quality.

  #### --expand_prompts

  Ask the VLM to create moderate, physically detailed generation prompts from the original prompt before video generation.

  #### --num_prompt_expansions

  Number of expanded generation prompts to request when `--expand_prompts` is used. The default is `4`.

  #### --base_seed

  Random seed for video generation. The default `-1` samples a fresh seed.

  #### --output_dir

  Directory where rendered views, generated videos, judgments, and final verdicts are saved.

  #### --overwrite

  Regenerate outputs even if files already exist.

  #### --refresh_judgments

  Re-run VLM scoring for existing videos without regenerating videos.

</details>
